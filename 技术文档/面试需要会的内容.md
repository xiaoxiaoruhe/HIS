  二、药房盘点单模块 — 需要会的内容

  这是你最能讲透的部分，四层模型设计得不错：

  ┌──────┬──────────────────────────┬──────────────────────────────────────────────────────┐
  │  层  │           实体           │                         作用                         │
  ├──────┼──────────────────────────┼──────────────────────────────────────────────────────┤
  │ 明细 │ WkfInventoryItem         │ 活库存记录（哪个物品、哪个批次、哪个仓库、多少数量） │
  ├──────┼──────────────────────────┼──────────────────────────────────────────────────────┤
  │ 锁   │ InventoryLock            │ 审批期间锁定库存，防止其他单据同时修改               │
  ├──────┼──────────────────────────┼──────────────────────────────────────────────────────┤
  │ 快照 │ DocInventoryItemSnapshot │ 提交审批时冻结库存状态，留审计痕迹                   │
  ├──────┼──────────────────────────┼──────────────────────────────────────────────────────┤
  │ 申请 │ WkfSupplyRequest         │ 盘点单主表 + 明细行（一个 busNo 聚合多行）           │
  └──────┴──────────────────────────┴──────────────────────────────────────────────────────┘

  核心状态流转（必须能画出来）：

  DRAFT → 提交审批（加锁+快照） → PENDING_APPROVAL
                                      ↓
                ← 撤回（释放锁+删快照）    审批通过（改库存+释放锁） → APPROVED
                                      ↓
                                审批拒绝（释放锁+保留快照） → REJECTED

  接口清单（9 个，要能说出每个干嘛的）：

  ┌─────────────────────────────────┬─────────────────────────────────────────┐
  │              接口               │                  作用                   │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ POST /pharmacy/create-order     │ 生成盘点单号（ABU+日期+序号）           │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ POST /pharmacy/save-order       │ 保存草稿（覆盖写入）                    │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ PUT /pharmacy/submit-approval   │ 提交审批 → 加锁 + 快照 + 状态变 PENDING │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ PUT /pharmacy/approve-approval  │ 审批通过 → 改库存数量 + 释放锁          │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ PUT /pharmacy/withdraw-approval │ 撤回 → 释放锁 + 删快照 + 回 DRAFT       │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ PUT /pharmacy/reject-approval   │ 拒绝 → 释放锁 + 保留快照                │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ POST /pharmacy/save-and-submit  │ 保存+提交一步到位                       │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ GET /pharmacy/order-list        │ 列表查询                                │
  ├─────────────────────────────────┼─────────────────────────────────────────┤
  │ GET /pharmacy/order-detail      │ 详情查询                                │
  └─────────────────────────────────┴─────────────────────────────────────────┘

  面试重点能说的：
  1. 为什么要加锁？→ 防止同一批库存被多个盘点单同时审批，导致数量冲突
  2. 为什么要快照？→ 审计需要，提交时的数量要冻结下来，即使后续库存变化也能追溯
  3. 乐观锁怎么做的？→ WHERE status_enum = 'DRAFT' 做状态校验，0 行更新就抛"状态已变更"
