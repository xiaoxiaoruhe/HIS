# 盘点单新增保存与查询接口实现过程（G8 + G9）

> 记录「分页查库存、新增单据、保存单据、保存并提交、单据列表、单据详情」六个接口从需求分析到编码的完整过程。审批流转（提交/通过/撤回/驳回）见《盘点单审批接口实现过程.md》。

## 1. 需求来源

接口文档 `接口文档.md` 中：

| 分组 | 功能 | 接口 |
|------|------|------|
| G8 | 盘点单新增保存 | 新增单据、保存单据、保存并提交审批 |
| G9 | 盘点单查询提交 | 获取单据列表、获取单据详情、提交审批 |

其中「提交审批」已在前一篇实现，本文覆盖其余 6 个接口。

## 2. 数据模型与字段映射

### 2.1 涉及的表

| 表 | 角色 |
|----|------|
| `wkf_supply_request` | 单据明细表（同表多行，一个 bus_no 多行明细） |
| `wkf_inventory_item` | 库存表（账面数量、批号、单位的来源） |

### 2.2 界面操作 → 字段映射

盘点单的交互是「选药房 + 类型 → 从库存选物品 → 填实盘数 → 保存」。对应到字段：

| 界面操作 | 字段 |
|----------|------|
| 选择盘点药房 | `purpose_location_id` |
| 选择项目类型 | `type_enum` / `category_enum` |
| 行中的项目名称 | `item_id` |
| 带出的盘点信息 | 库存 `wkf_inventory_item`（账面数量、批号、单位） |
| 手填的实盘数量 | `total_quantity` |
| 盈亏（实盘-账面） | `item_quantity` |

### 2.3 关键约定

- **单号**：`ABU + yyyyMMdd + 全局递增序号`（序号不按天重置）
- **盈亏**：前端算好传 `item_quantity`，后端只存不计算（线下人工盘点，后端不参与计算）
- **保存语义**：覆盖式，先删旧草稿明细再插新明细

## 5. 实现步骤

### 5.1 分页查库存

**Service 实现**（`WkfInventoryItemServiceImpl`）—— 用 MyBatis-Plus 声明式分页，只做 name 模糊：

```java
@Override
public PageDTO<InventoryItemVO> queryInventoryPage(InventoryItemQuery query) {
    Page<WkfInventoryItem> page = new Page<>(query.getPageIndex(), query.getPageSize());
    LambdaQueryWrapper<WkfInventoryItem> wrapper = new LambdaQueryWrapper<>();
    wrapper.like(WkfInventoryItem::getName, query.getName());
    return PageDTO.create(this.page(page, wrapper), InventoryItemVO::new);
}
```

要点：不写 XML、不加多余条件（库房、排序等），`PageDTO.create` 用 `BeanUtil.copyProperties` 把实体转 VO（字段名一致即可自动复制）。

### 5.2 新增单据

**Mapper** —— 查全局最大单号：

```xml
<select id="selectMaxBusNo" resultType="java.lang.String">
    SELECT MAX(bus_no) FROM wkf_supply_request WHERE is_deleted = 0
</select>
```

**Service** —— 生成单号（全局递增）：

```java
@Override
public String createOrder() {
    String date = LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMMdd"));
    String maxBusNo = wkfSupplyRequestMapper.selectMaxBusNo();
    int seq = 1;
    if (StringUtils.hasText(maxBusNo) && maxBusNo.length() > 11) {
        seq = Integer.parseInt(maxBusNo.substring(11)) + 1;
    }
    return "ABU" + date + String.format("%04d", seq);
}
```

要点：`substring(11)` 去掉 `ABU`(3位) + 日期(8位) = 11 位，剩下就是序号；`%04d` 固定序号 4 位。

### 5.3 保存单据

**Mapper** —— 删除草稿明细：

```xml
<delete id="deleteDraftByBusNo">
    DELETE FROM wkf_supply_request
    WHERE bus_no = #{busNo} AND is_deleted = 0 AND status_enum = 'DRAFT'
</delete>
```

**Service** —— 覆盖式写草稿：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void saveOrder(StocktakeOrderDTO dto) {
    // 1. 判空 busNo、明细列表
    // 2. 查该 busNo 现有明细，校验状态：非 DRAFT 抛"单据已提交或已审批,不能保存"
    // 3. deleteDraftByBusNo 先删旧草稿
    // 4. 循环插入新明细：statusEnum=DRAFT，表头字段(typeEnum/categoryEnum/locationId)落到每行
    //    createdBy/createdAt 由服务端填
}
```

要点：覆盖式（先删后插）支持反复改草稿；仅 DRAFT 可保存，已提交/审批的单据不允许改。

### 5.4 保存并提交审批

**Service** —— 保存 + 复用提交：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public InventoryOrderApprovalVO saveAndSubmit(StocktakeOrderDTO dto) {
    saveOrder(dto);
    OperatorDTO operatorDTO = new OperatorDTO();
    operatorDTO.setBusNo(dto.getBusNo());
    operatorDTO.setCreatedBy(dto.getCreatedBy());
    return submitApproval(operatorDTO);
}
```

要点：`saveOrder` + `submitApproval` 都标 `@Transactional`，Spring 默认传播机制合并成同一事务，要么全成功要么全回滚。

### 5.5 获取单据列表

**Mapper** —— 按 bus_no 聚合：

```xml
<select id="queryOrderList" resultType="...InventoryOrderApprovalVO">
    SELECT bus_no,
           MAX(status_enum) AS status_enum,
           MAX(created_by) AS created_by,
           MAX(created_at) AS created_at,
           MAX(approver_id) AS approver_id,
           MAX(approval_time) AS updated_at,
           SUM(COALESCE(total_price, 0)) AS total_price
    FROM wkf_supply_request
    WHERE is_deleted = 0
    GROUP BY bus_no
    ORDER BY MAX(created_at) DESC
</select>
```

要点：`GROUP BY bus_no` 把同表多行聚合成"每个单据一条"；`MAX` 是取代表值（状态/制单人每行相同），`SUM` 才是真聚合（累加金额），`COALESCE` 处理 NULL。

## 6. 关键设计决策

1. **单号全局递增而非按天重置**：`selectMaxBusNo` 查全局最大，不按 `LIKE 'ABU日期%'` 过滤，序号一直往上涨。代价是序号会越来越大，但避免了按天重置的复杂度。

2. **盈亏前端算，后端不碰**：盘点线下人工数数，实盘/盈亏都是人填的，后端只存 `itemQuantity`，不查库存账面去算。这也是为什么保存草稿阶段不校验库存。

3. **覆盖式保存 + 状态防线**：先删后插支持反复改草稿；保存前校验「非 DRAFT 不能保存」，防止改已提交的单据（否则锁和快照就乱了）。

4. **查库存用声明式分页**：`LambdaQueryWrapper` + `Page`，只做 name 模糊，不写 XML、不加多余条件。

5. **保存并提交的事务串联**：`saveOrder` 和 `submitApproval` 合并成一个事务，不会出现"明细存了但没提交"或"提交了但明细没存"的中间态。
