# 盘点单审批流程测试案例

## 1. 接口概览

服务地址：`http://192.168.1.7:10100`（context-path 为 `/`）

| 接口 | 方法 | 路径 | 入参 | 状态流转 |
|------|------|------|------|----------|
| 提交审批 | PUT | `/pharmacy/submit-approval` | OperatorDTO | DRAFT → PENDING_APPROVAL |
| 审批通过 | PUT | `/pharmacy/approve-approval` | ApprovalDTO | PENDING_APPROVAL → APPROVED |
| 撤回审批 | PUT | `/pharmacy/withdraw-approval` | OperatorDTO | PENDING_APPROVAL → DRAFT |
| 驳回审批 | PUT | `/pharmacy/reject-approval` | ApprovalDTO | PENDING_APPROVAL → REJECTED |

## 2. 状态机

```
DRAFT ──提交──> PENDING_APPROVAL ──通过──> APPROVED
                    │
                    ├──撤回──> DRAFT
                    └──驳回──> REJECTED
```

## 3. 测试数据说明

| 数据项 | 取值 | 说明 |
|--------|------|------|
| busNo | `ABU2026082001` | 盘点单号（ABU+yyyyMMdd+2位序号） |
| createdBy | `322932096091820032` | 制单人ID（库管 kuguan） |
| approverId | `322932010666430464` | 审批人ID（药房 yaofang） |

### 3.1 初始化测试数据（SQL）

执行下面的 SQL 准备一条草稿盘点单和对应的库存项，再开始测审批流程：

```sql
-- 1. 清理旧测试数据（重复执行前先清理，避免快照唯一索引冲突）
DELETE FROM wkf_supply_request WHERE bus_no = 'ABU2026082001';
DELETE FROM inventory_lock WHERE bus_no = 'ABU2026082001';
DELETE FROM doc_inventory_item_snapshot WHERE bus_no = 'ABU2026082001';
DELETE FROM wkf_inventory_item WHERE id = 'INV_TEST_001';

-- 2. 插入库存项（账面数量 100，提交后会被锁定，审批通过后平账为 98）
INSERT INTO wkf_inventory_item
(id, tenant_id, created_at, created_by, is_deleted, version,
 item_table, item_id, name, inventory_status_enum, supplier_id, unit_code, quantity, lot_number, location_id)
VALUES
('INV_TEST_001', '1', '2026-08-20 10:00:00', '322932096091820032', 0, 0,
 'med_medication_definition', 'MED_TEST_001', '阿莫西林胶囊', 'ACTIVE', 'SUP_TEST_001', '盒', 100.00, 'LOT20260801', 'WH_TEST_001');

-- 3. 插入草稿状态的盘点单明细（实盘 98，item_quantity 为盈亏 -2）
-- 说明：type_enum/category_enum 仅为满足非空约束，审批流程不校验这两个值
INSERT INTO wkf_supply_request
(id, tenant_id, created_at, created_by, is_deleted, version,
 bus_no, type_enum, status_enum, category_enum, item_table,
 item_quantity, total_quantity, item_id, unit_code, applicant_id,
 lot_number, purpose_location_id, price, total_price)
VALUES
('REQ_TEST_001', '1', '2026-08-20 10:00:00', '322932096091820032', 0, 0,
 'ABU2026082001', 'STOCKTAKE', 'DRAFT', 'INVENTORY', 'med_medication_definition',
 -2.00, 98.00, 'MED_TEST_001', '盒', '322932096091820032',
 'LOT20260801', 'WH_TEST_001', 12.500000, 1225.000000);
```

> 关键对应关系：明细的 `item_id + lot_number + purpose_location_id` 必须等于库存项的 `item_id + lot_number + location_id`，否则提交时找不到库存项（报"库存不存在"）。

## 4. 提交审批（submitApproval）

核心动作：验锁 → 加锁 → 冻结账面快照 → 改状态 DRAFT → PENDING_APPROVAL。

| 用例 | 名称 | 前置条件 | 输入 | 预期结果 |
|------|------|----------|------|----------|
| 1.1 | 提交成功 | 单据状态为 DRAFT，库存存在且未被锁定，明细无重复 | 见下方 JSON | 返回 `statusEnum=PENDING_APPROVAL`；生成锁记录、快照记录；库存被锁定 |
| 1.2 | DTO 为空 | 无 | 请求体为空 / busNo 为空 | 抛 `IllegalArgumentException`：DTO或busNo不能为空 |
| 1.3 | 单据无明细 | busNo 在 wkf_supply_request 无记录 | busNo 不存在 | 抛 `IllegalArgumentException`：当前单据下无明细 |
| 1.4 | 非草稿状态 | 单据状态已是 PENDING_APPROVAL/APPROVED 等 | 正常入参 | 抛 `IllegalArgumentException`：当前单据不是草稿状态 |
| 1.5 | 明细重复 | 同一库存项（物品+批号+库房）出现两次 | 见下方 JSON | 抛 `IllegalArgumentException`：单据存在重复明细 |
| 1.6 | 库存不存在 | 明细对应的库存项不存在 | 正常入参 | 抛 `IllegalArgumentException`：库存不存在 |
| 1.7 | 库存已被其它单据锁定 | 库存项已被其它 busNo 锁定 | 正常入参 | 抛 `IllegalStateException`：库存项已被单据 xxx 锁定 |

用例 1.1 请求体：

```json
{
  "busNo": "ABU2026082001",
  "createdBy": "322932096091820032"
}
```

## 5. 审批通过（approveApproval）

核心动作：平账（账面=实盘）→ 释放锁 → 改状态 PENDING_APPROVAL → APPROVED。

| 用例 | 名称 | 前置条件 | 输入 | 预期结果 |
|------|------|----------|------|----------|
| 2.1 | 审批通过 | 状态为 PENDING_APPROVAL，实盘数量已录入 | 见下方 JSON | 返回 `statusEnum=APPROVED`；库存账面数对齐实盘；锁被释放（lock_flag=0） |
| 2.2 | DTO 为空 | 无 | busNo 或 approverId 为空 | 抛 `IllegalArgumentException`：DTO、busNo或审批人不能为空 |
| 2.3 | 非待审批状态 | 状态不是 PENDING_APPROVAL | 正常入参 | 抛 `IllegalArgumentException`：当前单据不是待审批状态 |
| 2.4 | 库存不存在 | 明细对应库存项不存在 | 正常入参 | 抛 `IllegalArgumentException`：库存不存在 |
| 2.5 | 实盘数未录入 | 明细 total_quantity 为 null | 正常入参 | 抛 `IllegalArgumentException`：实盘数量未录入,无法通过审批 |

用例 2.1 请求体：

```json
{
  "busNo": "ABU2026082001",
  "approverId": "322932010666430464"
}
```

## 6. 撤回审批（withdrawApproval）

核心动作：释放锁 → 删除快照 → 改状态 PENDING_APPROVAL → DRAFT（清空申请人与申请时间）。

| 用例 | 名称 | 前置条件 | 输入 | 预期结果 |
|------|------|----------|------|----------|
| 3.1 | 撤回成功 | 状态为 PENDING_APPROVAL | 见下方 JSON | 返回 `statusEnum=DRAFT`；锁被释放；快照被物理删除；可重新提交 |
| 3.2 | DTO 为空 | 无 | busNo 为空 | 抛 `IllegalArgumentException`：DTO或busNo不能为空 |
| 3.3 | 非待审批状态 | 状态不是 PENDING_APPROVAL | 正常入参 | 抛 `IllegalArgumentException`：当前单据不是待审批状态 |

用例 3.1 请求体：

```json
{
  "busNo": "ABU2026082001",
  "createdBy": "322932096091820032"
}
```

## 7. 驳回审批（rejectApproval）

核心动作：释放锁 → 改状态 PENDING_APPROVAL → REJECTED（写入审批人、审批时间与驳回原因，快照保留作审计）。

| 用例 | 名称 | 前置条件 | 输入 | 预期结果 |
|------|------|----------|------|----------|
| 4.1 | 驳回成功 | 状态为 PENDING_APPROVAL | 见下方 JSON | 返回 `statusEnum=REJECTED`；锁被释放；remark 写入 reason 字段；快照保留 |
| 4.2 | DTO 为空 | 无 | busNo 或 approverId 为空 | 抛 `IllegalArgumentException`：DTO、busNo或审批人不能为空 |
| 4.3 | 非待审批状态 | 状态不是 PENDING_APPROVAL | 正常入参 | 抛 `IllegalArgumentException`：当前单据不是待审批状态 |

用例 4.1 请求体：

```json
{
  "busNo": "ABU2026082001",
  "approverId": "322932010666430464",
  "remark": "实盘数量与账面差异较大，请核对后重新提交"
}
```

## 8. 完整流转链路（冒烟测试）

按顺序执行，验证状态机闭环：

1. **提交审批**（用例 1.1）→ 状态 PENDING_APPROVAL，库存锁定，快照生成
2. **撤回审批**（用例 3.1）→ 状态回到 DRAFT，锁释放，快照删除
3. **再次提交审批**（用例 1.1）→ 状态 PENDING_APPROVAL（验证撤回后可重提、快照不冲突）
4. **驳回审批**（用例 4.1）→ 状态 REJECTED，锁释放
5. （另一单据走通过链路）**提交审批** → **审批通过**（用例 2.1）→ 状态 APPROVED，账面=实盘
