# 面试准备指南

本文档整理了面试中需要重点掌握的三个核心模块，按优先级排序，帮助你高效备考。

## 一、OAuth2 认证授权模块

### 1.1 核心文件与职责

你现有的 11 个文件按功能可划分为以下 5 个模块：

| 功能块 | 核心类 | 面试要点 |
|--------|--------|----------|
| 认证入口 | `LoadUserDetailServiceImpl` | 根据 `clientId` 分流管理端/用户端，查用户 → 查角色 → 查医务人员 → 组装 `SecurityUser` |
| Token 增强 | `TokenEnhancerDataServiceImpl` | 在 JWT 中额外注入 `userId` 等业务字段 |
| Token 存储 | `RedisOauth2AuthorizationServiceImpl` | 将 OAuth2 的 `access_token`、`refresh_token`、`authorization_code` 存储到 Redis，并管理 TTL |
| 权限缓存 | `ResourcesServiceImpl` + `ResourcesCacheController` | 启动时将 `{接口URL: [角色列表]}` 加载到 Redis，并提供手动刷新接口 |
| 配置 | `Oauth2Config` + `Oauth2Properties` | 跨域配置、Redis 授权服务注册、`clientId` 配置 |
| 登录页 | `LoginController` | 渲染登录页面，传递 `clientId` |

### 1.2 面试标准回答

> 用户登录时，框架会调用我编写的 `LoadUserDetailService` 来加载用户信息。我根据 `clientId` 判断是管理端还是用户端，然后分别查询用户表、角色表和医务人员表，组装成 `SecurityUser` 返回。Token 生成时，`TokenEnhancer` 会向 JWT 中注入 `userId` 等业务字段。系统启动时，会将接口与角色的映射关系预先加载到 Redis 中，网关拦截请求时从 Redis 校验权限。

### 1.3 Gateway 侧核心类

| 类名 | 作用 |
|------|------|
| `GatewayConfig` | 通过 `@EnableZoGateway` 注解开启网关 |
| `LoadResourcesDataImpl` | 网关从 Redis 查询 URL 对应的角色列表 |
| `TokenExtendsValidateImpl` | 网关校验 Token 的扩展信息 |

## 二、药房盘点单模块

> 这是你最核心的亮点模块，四层模型设计思路清晰，面试时重点展开。

### 2.1 核心实体与职责

| 层次 | 实体类 | 职责说明 |
|------|--------|----------|
| 明细 | `WkfInventoryItem` | 活库存记录，记录哪个物品、哪个批次、哪个仓库、多少数量 |
| 锁 | `InventoryLock` | 审批期间锁定库存，防止其他单据同时修改 |
| 快照 | `DocInventoryItemSnapshot` | 提交审批时冻结库存状态，留存审计痕迹 |
| 申请 | `WkfSupplyRequest` | 盘点单主表 + 明细行（一个 `busNo` 聚合多行） |

### 2.2 核心状态流转

```
DRAFT
  │
  ├─ 提交审批（加锁 + 快照） ──→ PENDING_APPROVAL
  │                              │
  │                       ┌──────┴──────┐
  │                       ↓             ↓
  │              审批通过        审批拒绝
  │              (改库存+释放锁)  (释放锁+保留快照)
  │                       ↓             ↓
  │                   APPROVED      REJECTED
  │
  └─ 撤回（释放锁 + 删快照） ──→ DRAFT
```

### 2.3 接口清单

| 接口路径 | 方法 | 作用 |
|----------|------|------|
| `/pharmacy/create-order` | POST | 生成盘点单号（格式：ABU + 日期 + 序号） |
| `/pharmacy/save-order` | POST | 保存草稿（覆盖写入） |
| `/pharmacy/submit-approval` | PUT | 提交审批 → 加锁 + 快照 + 状态变更为 PENDING |
| `/pharmacy/approve-approval` | PUT | 审批通过 → 修改库存数量 + 释放锁 |
| `/pharmacy/withdraw-approval` | PUT | 撤回 → 释放锁 + 删除快照 + 回退到 DRAFT |
| `/pharmacy/reject-approval` | PUT | 拒绝 → 释放锁 + 保留快照 |
| `/pharmacy/save-and-submit` | POST | 保存 + 提交一步到位 |
| `/pharmacy/order-list` | GET | 列表查询 |
| `/pharmacy/order-detail` | GET | 详情查询 |

### 2.4 面试高频问题

**Q1：为什么要加锁？**

A：防止同一批库存被多个盘点单同时审批，导致库存数量冲突。

**Q2：为什么要快照？**

A：审计需要。提交审批时的库存状态必须冻结下来，即使后续库存发生变化，也能追溯当时的状态。

**Q3：乐观锁是怎么实现的？**

A：通过 `WHERE status_enum = 'DRAFT'` 做状态校验，如果更新行数为 0，则说明状态已被其他操作修改，抛出"状态已变更"异常。

## 三、MCP / Spring AI 模块

### 3.1 架构链路

```
用户
  │
  ▼
his-sample-ai（AI 助手服务）
  ├── /ai/chat      → 直接与大模型对话，不调用工具
  ├── /ai/data      → ReactAgent（大模型 + MCP 工具）执行数据管理
  └── /ai/travel    → 远程 Travel Agent（A2A 协议）执行旅行规划
                          │
                          ▼
              his-sample-agent-travel（独立微服务）
                          │
                          ▼
                his-mcp-gateway（MCP 工具聚合层）
                          │
                          ▼
                外部 MCP Server（如 12306 铁路查询）
```

### 3.2 核心概念

| 概念 | 说明 |
|------|------|
| MCP 是什么 | Model Context Protocol，大模型调用外部工具的标准协议，让 LLM 能像调用 API 一样调用服务 |
| MCP Gateway 的作用 | 聚合多个 MCP Server 的工具能力，通过 Nacos 注册发现，AI 服务无需直连每个 Server |
| ReactAgent 是什么 | 基于 ReAct 模式（推理 + 行动），大模型自主决定是否需要调用工具、调用哪个工具，拿到结果后继续推理 |
| A2A 是什么 | Agent-to-Agent 协议，一个 Agent 可以将请求委托给另一个远程 Agent 处理 |
| Token 如何传递 | `McpHeaderFilter` 提取请求头 → 存入 `RequestHeaderContext`（ThreadLocal） → 通过 `McpHeaderConfig` 注入到下游调用 |

### 3.3 面试标准回答

> 我们接入了 Spring AI，让大模型能够调用 HIS 系统的业务接口。通过 MCP 协议将工具统一注册到 Gateway，AI 服务可以自动发现并调用这些工具。同时还接入了 A2A 协议，支持一个 Agent 将请求转发给另一个专业 Agent 来处理，实现了 Agent 之间的协作。

## 四、总结：掌握优先级

| 优先级 | 模块 | 原因 |
|--------|------|------|
| **最高** | 药房盘点单 | 这是你从头到尾独立完成的业务模块，逻辑完整，能画状态机，面试最容易讲透 |
| **中** | OAuth2 | 框架由 Starter 提供，但业务填充部分是你完成的，能说清认证流程即可 |
| **低** | MCP / AI | 以配置型工作为主，了解核心概念和整体架构即可，无需深挖源码 |
